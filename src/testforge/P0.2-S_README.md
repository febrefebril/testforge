
# P0.2-S — Revisão de dados antes do Git

## Arquivos tocados e motivo

- `submission/models.py`: schemas Pydantic v2 de achados, decisões, scan e resultado.
- `submission/scanner.py`: scanner offline e hash determinístico da árvore original.
- `submission/service.py`: valida decisão e cria cópia sanitizada; não chama Git.
- `submission/__init__.py`: API pública do módulo.
- `cli/app.py`: comando `submit --dry-run`; auto-publicação é desabilitada quando a flag está ativa.
- `gui/recorder_launcher.py`: modal pós-gravação atrás de flag.
- `tests/test_submission_security.py`: testes unitários do incremento.

Nenhum arquivo da gravação original é modificado. A saída é criada em `submissions/<recording_id>/`.

## Ativação gradual

PowerShell:

```powershell
$env:TESTFORGE_SENSITIVE_REVIEW="1"
```

Com a flag ativa, a auto-publicação legada após `record` é interrompida. A GUI abre a revisão após o processo de gravação. Com a flag desligada, o fluxo antigo permanece.

## CLI

Somente analisar, sem escrever ou publicar:

```powershell
python -m testforge.cli.app submit dados_senssiveis --dry-run
```

Preparar cópia sanitizada, sem Git:

```powershell
python -m testforge.cli.app submit dados_senssiveis --environment DES
```

Preservar CPF/CNPJ controlados apenas neste pacote; segredos continuam sanitizados:

```powershell
python -m testforge.cli.app submit dados_senssiveis --environment DES --allow-test-data cpf,cnpj --reason "massa sintetica controlada DES"
```

Cancelar explicitamente:

```powershell
python -m testforge.cli.app submit dados_senssiveis --cancel
```

`submit` nunca chama o publisher Git. O pacote fica com `published=false` e status `prepared`. O comando legado `send` permanece separado para compatibilidade, mas não é acionado por `submit`.

## Regras

- CPF/CNPJ: sanitizados por padrão; podem ser preservados com justificativa explícita por envio.
- Senha, token, JWT, authorization code e code verifier: nunca podem ser preservados.
- `state`, `nonce`, `session_code` e `code_challenge`: sempre normalizados.
- Arquivos binários/opacos: excluídos da cópia mínima porque este incremento não consegue provar que são seguros; o original local permanece intacto.
- Se o scan final ainda encontrar segredo, a cópia é removida e a operação falha fechada.
- Não existe envio Git automático neste fluxo.

## Gate DES

### Objetivo
Validar a revisão e preparação segura da gravação antes do Git, permitindo massa controlada sem liberar segredos.

### Pré-condições
- `TESTFORGE_SENSITIVE_REVIEW=1`;
- gravação SIFAP preservada em local controlado;
- repositório de teste isolado;
- testes unitários verdes;
- nenhuma submissão automática habilitada.

### Passos
1. Faça uma cópia controlada da gravação SIFAP.
2. Execute `submit <id> --dry-run`.
3. Confirme CPF/CNPJ no relatório.
4. Confirme senha, authorization code e code verifier como bloqueantes.
5. Confirme `state`, `nonce` e `session_code` com sanitização proposta.
6. Execute `submit <id> --cancel` e confirme que não surgiu `submissions/<id>` nem commit.
7. Abra a revisão pela GUI.
8. Autorize CPF/CNPJ como massa DES, com justificativa.
9. Prepare a cópia sanitizada.
10. Inspecione todos os arquivos em `submissions/<id>`.
11. Compare `source_sha256_before` e `source_sha256_after`.
12. Rode o scanner no pacote final.
13. Repita pela CLI com `--dry-run`.
14. Solicite revisão de um QA.

### Resultado esperado
- original intacto;
- CPF/CNPJ preservados somente com autorização específica;
- senha e tokens ausentes;
- material transitório normalizado;
- binários opacos ausentes da cópia;
- cancelamento sem pacote e sem commit;
- `published=false`;
- decisões válidas e serializadas em JSON.

### Aprovação
Avançar para P0.2-SSO somente com scan final sem segredo, regras idênticas no backend usado por GUI/CLI, testes verdes e revisão de um QA.

### Rollback
Desative a flag e reverta os arquivos deste incremento se um segredo puder ser preservado, o original mudar, um pacote surgir sem decisão, o scanner falhar aberto ou a GUI indicar envio que não ocorreu.
